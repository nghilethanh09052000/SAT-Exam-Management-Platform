# App Audit Handoff — 2026-05-20

Purpose: current-state snapshot for the next working session.

## Overall State

The project is a working internal alpha for a Vietnamese SAT management platform. The core loop exists:

- Admin manages users, students, and courses.
- Teacher manages courses, classes, weeks, question bank, imports, assignments, exam papers, and student views.
- Student sees assignments, takes a Bluebook-style test, gets results, and has an error log.
- Supabase migrations and RLS policies exist.
- A separate `pipeline/sat-pipeline` ETL project exists for scraping/cleaning/syncing SAT questions.

The app builds successfully with `pnpm exec next build`.

## Highest Priority Risks

### P0: Some API routes still allow authenticated users without role/ownership checks

Status: partially fixed on 2026-05-20.

Completed:

- `app/api/weeks/[id]/route.ts`
  - `PATCH` and `DELETE` now require active teacher/admin ownership through `assertTeacherOwnsWeek`.
- `app/api/assignment-instances/[id]/route.ts`
  - `PATCH` and `DELETE` now require active teacher/admin ownership through `assertTeacherOwnsAssignmentInstance`.
- Shared helpers now exist for `assertTeacherOwnsCourse`, `assertTeacherOwnsClass`, `assertTeacherOwnsWeek`, and `assertTeacherOwnsAssignmentInstance`.

Next fix: continue auditing the remaining `app/api/**` mutation routes and replace ad hoc checks with these helpers where applicable.

### P0: Attempt creation can still race

Status: fixed in code on 2026-05-20; requires applying the new migration in the target Supabase environment.

Completed:

- Added `supabase/migrations/00026_transactional_submission_attempt.sql`.
- New `public.create_submission_attempt(p_instance_id UUID)` function uses a transaction-scoped advisory lock keyed by assignment instance and student.
- The function validates auth, published assignment status, deadline, active student enrollment, and retake limit before inserting.
- `app/api/submissions/route.ts` and `app/(student)/student/test/[instanceId]/page.tsx` now use the RPC instead of count-then-insert logic.

Next fix: deploy the migration and run a two-tab/double-click smoke test against Supabase.

### P1: Question correctness can leak through student test payloads

Status: fixed on 2026-05-20.

Completed:

- `app/(student)/student/test/[instanceId]/page.tsx` no longer selects `question_options.is_correct` for the active test-taking payload.
- `app/(student)/student/test/[instanceId]/test-interface.tsx` no longer types active options with `is_correct`.
- Correctness is still used in submit/result/error-log flows where answer review is expected.

### P1: Test tooling is noisy/broken

Status: fixed on 2026-05-20.

Completed:

- Exclude `.claude/` from Jest and TypeScript.
- Fix `e2e/teacher-courses.spec.ts` helper typing by importing `Page` from `@playwright/test`.
- Updated stale login E2E copy/selectors to current `GD SAT Platform` login flow.

### P1: E2E specs are stale versus current UI copy

Status: partially fixed on 2026-05-20.

Completed:

- Updated auth, student-home, and teacher-course E2E specs away from stale `SAT Platform` and direct staff form assumptions.

Next fix: run the full Playwright suite against seeded Supabase credentials when an E2E environment is available.

### P1: Report modal does not persist

The student test report modal clears local state and closes, but it does not save a report.

Next fix: add a `question_reports` table/API and teacher/admin inbox view.
