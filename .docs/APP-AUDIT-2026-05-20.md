# App Audit Handoff — 2026-05-20

Purpose: current-state snapshot for the next working session.

## Overall State

The project is a working internal alpha for a Vietnamese SAT management platform. The core loop exists:

- Admin manages users, students, and courses.
- Teacher manages courses, classes, weeks, question bank, imports, assignments, exam papers, and student views.
- Student sees assignments, takes a Bluebook-style test, gets results, and has an error log.
- Supabase migrations and RLS policies exist.
- A separate `pipeline/sat-pipeline` ETL project exists for scraping/cleaning/syncing SAT questions.

The app builds successfully with `pnpm exec next build`.

## Highest Priority Risks

### P0: Some API routes still allow authenticated users without role/ownership checks

Several routes correctly improved auth checks, but some mutation routes still only verify that a user exists before updating/deleting a resource. Important examples:

- `app/api/weeks/[id]/route.ts`
  - `PATCH` and `DELETE` only check authentication, then use service role.
- `app/api/assignment-instances/[id]/route.ts`
  - `PATCH` and `DELETE` only check authentication and rely on RLS/service-client behavior unevenly.

Next fix: create shared auth helpers for `assertTeacherOwnsCourse`, `assertTeacherOwnsClass`, `assertTeacherOwnsWeek`, and `assertTeacherOwnsAssignmentInstance`; use them before every mutation.

### P0: Attempt creation can still race

`app/api/submissions/route.ts` checks attempt count before insert. This is good, but two fast requests can both count the same value and insert duplicate attempts.

Next fix: enforce attempt limits transactionally with a Postgres function/RPC or a database constraint strategy.

### P1: Question correctness can leak through student test payloads

The student test page selects `question_options(..., is_correct, ...)` while building the test payload. The client only maps id/label/content into `QuestionDisplay`, but the server component still fetched correctness for a student-facing test route.

Next fix: remove `is_correct` from the test-page query and keep answer keys only in submit/result server flows.

### P1: Test tooling is noisy/broken

- `pnpm exec next build` passes.
- `pnpm exec tsc --noEmit` fails on `e2e/teacher-courses.spec.ts` because of an invalid custom Playwright page type.
- `pnpm exec jest --runInBand` fails because Jest discovers Playwright specs inside `.claude/worktrees/**`.

Next fix:

- Exclude `.claude/` from Jest and TypeScript.
- Fix `e2e/teacher-courses.spec.ts` helper typing by importing `Page` from `@playwright/test`.

### P1: E2E specs are stale versus current UI copy

E2E tests still expect `SAT Platform` in places where the UI/docs indicate the app has moved toward `GD SAT Platform` and softer login copy.

Next fix: update E2E locators to stable role/label selectors and current copy.

### P1: Report modal does not persist

The student test report modal clears local state and closes, but it does not save a report.

Next fix: add a `question_reports` table/API and teacher/admin inbox view.
